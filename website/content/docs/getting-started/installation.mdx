gobento is released on [GitHub Releases](https://github.com/Tales-of-zuna/gobento/releases).
It is pre-1.0 and in early development, so the interface may still change between minor releases;
each release's notes list what changed.

## Requirements

- **Go 1.26 or newer.** gobento is a Go program, and it uses your local Go
  toolchain to fetch the exact dependency versions of the project it
  generates. The `go` command must be on your `PATH`.
- **Network access to the Go module proxy.** Generation downloads the selected
  module versions. Your `GOPROXY`, `GONOSUMDB`, and `GOPRIVATE` settings are
  respected.
- **No C compiler.** gobento and every supported stack (including SQLite)
  are pure Go, so cgo is not needed on Linux, macOS, or Windows.

## Install the CLI

You can install gobento with `go install` or download a prebuilt binary.

### With `go install`

```sh
go install github.com/Tales-of-zuna/gobento/cmd/gobento@latest
```

This builds the latest release into `$(go env GOBIN)`, or `$(go env GOPATH)/bin`
when `GOBIN` is not set. Make sure that directory is on your `PATH`. To install a
specific version, replace `@latest` with its tag, such as `@v0.1.0`.

### With a prebuilt binary

Each release on the
[releases page](https://github.com/Tales-of-zuna/gobento/releases) has an
archive for Linux, macOS, and Windows on `amd64` and `arm64`, named
`gobento_<version>_<os>_<arch>` (`.tar.gz`, or `.zip` on Windows), and a
`checksums.txt` file with the SHA-256 checksum of every archive. The binaries
do not need Go to start, but generating a project still needs the Go toolchain
(see [Requirements](#requirements)).

Download the archive for your system and `checksums.txt`, from the releases
page or with the [GitHub CLI](https://cli.github.com/):

```sh
gh release download v0.1.0 --repo Tales-of-zuna/gobento \
  --pattern 'gobento_0.1.0_linux_amd64.tar.gz' --pattern checksums.txt
```

Verify the checksum before you run the binary:

<Tabs items={['Linux', 'macOS', 'Windows (PowerShell)']}>
<Tab value="Linux">

```sh
sha256sum --check --ignore-missing checksums.txt
```

It prints `gobento_0.1.0_linux_amd64.tar.gz: OK`.

</Tab>
<Tab value="macOS">

```sh
shasum -a 256 --check --ignore-missing checksums.txt
```

It prints `OK` after the archive's name.

</Tab>
<Tab value="Windows (PowerShell)">

```powershell
$file = "gobento_0.1.0_windows_amd64.zip"
$want = (Select-String -Path checksums.txt -Pattern $file -SimpleMatch).Line.Split(" ")[0]
(Get-FileHash $file -Algorithm SHA256).Hash -eq $want
```

It prints `True` when the hash matches the archive's line in `checksums.txt`.

</Tab>
</Tabs>

Extract the archive, which contains `gobento` (`gobento.exe` on Windows),
`LICENSE`, and `README.md`, and move the binary to a directory on your `PATH`:

```sh
tar -xzf gobento_0.1.0_linux_amd64.tar.gz gobento
sudo mv gobento /usr/local/bin/
```

On Windows, extract the `.zip` (for example with `Expand-Archive`) and add the
folder that holds `gobento.exe` to your `PATH`.

### Check the installation

```sh
gobento --version
```

A release binary prints its version, such as `gobento version 0.1.0`.
gobento v0.1.0 installed with `go install` prints `gobento version dev`: that
release only reports the version that release builds set. Releases after
v0.1.0 also report the module version when installed with `go install`.

### Build from source

To build from a clone instead, run `make build` (or
`go build -o bin/gobento ./cmd/gobento`), which writes `bin/gobento`.

## Go version of generated projects

The Go version of the tool you install and the Go version of the projects you
generate are separate. Each generated project gets its `go` directive from the
[version rules](/docs/concepts/version-rules), and you can choose another
supported one with `--go`.

Before writing anything, gobento compares the selected Go version with your
local toolchain:

- If the selected version is newer and `GOTOOLCHAIN` forbids downloads
  (`local`, `path`, or a value ending in `+path`), gobento stops with an error
  naming both versions.
- If the selected version is newer otherwise, gobento warns that Go will
  download the newer toolchain.
- If no `go` command is found, gobento stops with instructions to install Go.
