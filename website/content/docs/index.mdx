## What gobento is

gobento is a command-line tool that generates a new Go project from the stack
you pick: an architecture, an HTTP framework, a database, and a data-access
library.

```sh
gobento new shop --module example.com/shop --framework chi
```

The generated project builds, passes `go vet` and `gofmt`, and passes its own
tests without any edits from you.

## Why it exists

Project generators often hard-code tool versions in their templates and grow
one template per combination of options. They fall behind upstream releases,
and every new option multiplies the work.

gobento avoids both problems:

- **Your stack, your choice.** You select one component of each kind. Flags
  are only required when a kind has more than one option.
- **Versions as data.** All supported Go and module versions live in one rules
  file. You can choose versions inside the supported ranges, and gobento
  rejects combinations that do not work instead of silently changing them.
- **Composed, not copy-pasted.** An architecture defines slots with Go
  contracts between them, and components fill the slots. There is no template
  per combination.
- **Safe to run anywhere.** Every input problem is reported at once, before
  anything is written. gobento only fills a new or empty directory, and on any
  failure or Ctrl-C it leaves nothing behind.
- **Proven builds.** Every supported combination is generated, built, and
  tested in CI on Linux, macOS, and Windows.

gobento is inspired by [go-blueprint](https://github.com/melkeydev/go-blueprint),
which showed how much a good project generator helps Go developers get
started.

## What you can choose today

| Kind           | Components                                                  |
| -------------- | ----------------------------------------------------------- |
| Architecture   | `mvc` (Model-View-Controller)                               |
| HTTP framework | `nethttp` (the standard library's `net/http`), `chi`, `gin` |
| Database       | `sqlite` (pure Go, no cgo)                                  |
| Data access    | `sqlc`                                                      |

Every selection generates a project with a health endpoint and one example
resource, `/items`, stored in SQLite. All frameworks serve exactly the same
API. More databases, data-access libraries, and architectures are on the
roadmap; the
[Components](/docs/components) reference always lists exactly what the
catalog supports.
